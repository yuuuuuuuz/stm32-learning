# STM32F103 舵机 PWM 工程 —— 上电回到 0 度

把舵机接上，烧进去，上电它就会自己走到 **0 度（1000µs）** 并停在那里。

---

## 1. 先确认你的舵机是哪种（很重要）

| | 位置型舵机 | 连续旋转型舵机 |
|---|---|---|
| 典型型号 | SG90 / MG996R / 20kg 数字舵机 | "360° 舵机" |
| 脉宽含义 | **角度** | **速度** |
| 1000µs | 0 度 | 全速正转（永不停） |
| 1500µs | 中位 90 度 | **停止** |
| 2000µs | 180 度 | 全速反转（永不停） |
| 用手转输出轴 | 转 ~180–270° 就卡住 | 能无限圈地转下去 |

**5 秒判断法**：断电，用手捏住舵盘转。
- 转到某个角度卡住、转不过去 → **位置型**，本工程默认就是给它写的
- 能一圈一圈无限转 → **连续旋转型**，它没有"0 度"这回事，只有"停"

如果是连续旋转型，打开 `User/main.c`，把这一行改成 1：

```c
#define SERVO_IS_CONTINUOUS     0     // 改成 1
```

程序就变成"上电即输出 1500µs 让舵机停住"。

## 2. 接线

```
舵机 橙/黄/白 (信号)  ->  PA0   (TIM2_CH1)
舵机 红      (电源+)  ->  独立 5V 电源正极      ★ 别接板子的 3.3V
舵机 棕/黑   (电源-)  ->  独立 5V 电源负极
                         并且必须和板子的 GND 连在一起（共地）
板载 LED              ->  PC13（不用接线）
```

**最容易犯的两个错：**

1. **舵机电源的地没有和 STM32 板子的 GND 连在一起。**
   实测现象：舵机**完全没反应、不响、不热、像没通电**——因为没信号它就不出力。
   ⚠️ 注意不是"乱抖"。很多人以为会抖，实际是彻底沉默，很容易误判成舵机坏了。
   ★ 只要给舵机用了独立电源，就必须把两个 GND 接起来。

2. **MG996R 用板子的 5V 供电** → 堵转电流 2.5A，板子直接掉电复位。

## 3. 排障：舵机完全不动

按这个表从上往下查：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 完全没反应，不响不热 | **没共地**（占绝大多数） | 独立电源 GND 接到板子 GND |
| 完全没反应 | 信号线没真的插在 PA0 | 换根杜邦线，量通断 |
| 完全没反应 | "独立 5V"其实没输出 | 万用表量舵机红线对黑线应有 5V |
| 嗡嗡响、发烫、不转 | 脉宽顶到机械限位堵转 | 把 `PULSE_0DEG`/`PULSE_180DEG` 往中间收 |
| 一直朝一个方向转不停 | 是连续旋转型舵机 | `main.c` 里 `SERVO_IS_CONTINUOUS` 改 1 |
| 乱抖、位置飘 | 供电电流不够 | 换更大的电源 |

**万用表一步定位**：红表笔接舵机信号线（橙/黄/白），黑表笔接舵机黑线（GND），直流电压档：

| 读数 | 含义 |
|---|---|
| 约 **0.16V** | 脉宽 1000µs 时的平均值 → 信号通了、地也通了 |
| 约 **0.33V** | 脉宽 2000µs 时 |
| **0V** | 信号没到，或地没通 |
| **5V 不变** | 插头插反了，把电源当信号接了 |

这个测量的好处是**它同时验证信号线和共地**：黑表笔搭在舵机的 GND 上，
如果地不共，量到的就是悬空值。

**终极定位手段**：跑扫动测试，它通过调试器直接改 `TIM2->CCR1`，
让 PA0 在 0° 和 180° 之间来回扫 30 秒：

```powershell
powershell -ExecutionPolicy Bypass -File sweep.ps1
```

舵机跟着摆 → 接线没问题；纹丝不动 → 信号确实没到舵机。

## 5. 烧录

```powershell
powershell -ExecutionPolicy Bypass -File flash.ps1
```

脚本会先烧录，然后**从芯片里把 Flash 读回来逐字节比对**，确认真的写进去了。
烧录前请关掉 Keil 的在线调试，否则会抢同一个调试器。

校验用的是 `verify.py`（直接调 pyOCD 的 Python API）。不用
`pyocd commander -c "save ..."` 是因为 pyocd 0.45.1 的 `save` 命令有 bug，
对文件参数一律报 `Error: invalid argument`，绝对路径和相对路径都一样。

## 6. 想改角度 / 改行为

全在 `User/main.c` 顶部的配置区：

```c
#define SERVO_IS_CONTINUOUS     0      // 0=位置型  1=连续旋转型
#define DEMO_SWEEP              0      // 1=回 0 度后做一次往返演示

#define PULSE_0DEG              1000u  // 0 度对应脉宽
#define PULSE_CENTER            1500u  // 中位
#define PULSE_180DEG            2000u  // 180 度
```

代码里随时可以调角度：

```c
Servo_SetAngle(90);        // 去 90 度
Servo_SetPulse(1200);      // 直接给脉宽 1200us
```

**如果舵机顶到机械限位后持续嗡嗡响、发烫**：说明脉宽超出了它自己的实际行程。
把 `PULSE_0DEG` / `PULSE_180DEG` 各往中间收 50~100µs。

## 7. 关键参数是怎么来的

```
TIM2 时钟 72MHz
  ÷ (PSC+1) = ÷72      -> 计数频率 1MHz     -> 1 个计数 = 1µs
  ARR = 19999          -> 周期 20000µs = 20ms -> 50Hz
  CCR = 1000           -> 高电平 1000µs
```

因为计数频率刚好是 1MHz，**CCR 的值直接就是脉宽微秒数**，不用换算。
`Servo_SetPulse(1000)` 就是 1000µs。

## 8. 搬进 Keil 工程

`User/main.c` 是纯标准外设库（SPL）写法，可以直接复制到你的 Keil 工程：

1. 把 `User/main.c` 的内容覆盖你 Keil 工程的 `User/main.c`
2. 确认工程里已经加入了 `stm32f10x_rcc.c` / `stm32f10x_gpio.c` / `stm32f10x_tim.c` / `misc.c`
3. `stm32f10x_conf.h` 里要打开 `tim`、`gpio`、`rcc`、`misc` 这几个头文件

> 本工程的 `startup_stm32f10x_md_gcc.s` 是给 GCC 用的，Keil 工程请继续用自带的
> `startup_stm32f10x_md.s`，不要替换。

## 10. 实测记录（这台舵机）

| 项目 | 实测值 |
|---|---|
| 机械限位（小端） | 约 **900 µs** —— 再往小就顶住不动 / 嗡嗡响 |
| 机械限位（大端） | 探到 **2500 µs** 仍未见明显堵转（未最终确认） |
| 固件 0 度位置 | 1000 µs |
| 固件中位 | 1500 µs |

**提醒**：0 度（1000µs）距离小端机械限位只有约 **100µs**。如果以后发现舵机
停在 0 度时**有轻微嗡嗡声或发热**，说明它其实顶在限位上，把 `User/main.c`
里的 `PULSE_0DEG` 改成 1020~1050 即可。

> 测法：`powershell -ExecutionPolicy Bypass -File range.ps1`
> 普通 PWM 舵机没有角度回读，芯片不知道舵机转到哪，所以必须由人盯着舵机
> 判断，脚本只负责把脉宽一步一步喂出去。

## 11. 调试器连不上（SWD No ACK）怎么办

**现象**：`pyocd` 报

```
SWD/JTAG communication failure (No ACK); check USB cable, reduce debugger clock
```

但同时：

- `pyocd list` 还能看到调试器，COM3 也还在
- 降到 100kHz / 10kHz 都没用
- 换 JTAG 协议也一样失败

**怎么判断是"调试器好、线断了"**：

```powershell
pyocd commander -N -t cortex_m -c "show target"
```

`-N` 表示不初始化调试系统。调试器本身正常的话这条命令能跑起来，并显示：

```
DAP IDCODE:   0x00000000     ← 全 0 = 芯片那侧完全没应答
```

正常应该是 `0x1BA01477`。**IDCODE 全 0 就说明调试器在正常发信号，但线没接到
芯片上**（或者是 GND 没通）。

**先试这个（成功率很高）**：把调试器的 USB **拔掉、等 5 秒、再插上**。
CMSIS-DAP 固件偶尔会卡在错误状态，重新枚举一次就好了 —— 本工程开发过程中
遇到过一次，就是这么解决的。

还不行再按顺序查：

1. 调试器和板子之间的 **GND** 有没有连上（最常见）
2. SWDIO → PA13、SWCLK → PA14 有没有插对、插紧
3. 舵机的线有没有碰到 SWD 引脚造成短路 —— 把舵机线**全拔掉**再试
4. 板子还有没有电（电源灯亮不亮）

**不需要调试器也能判断板子和固件是否还活着**：用手碰一下舵盘，
如果它**有保持力矩**，说明固件在跑、PA0 还在输出 PWM，那就纯属调试线的
问题，不用慌。
